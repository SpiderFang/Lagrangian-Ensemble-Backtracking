## 1. 問題重述

`src/lagrangian_backtracking/input_derivation.py` 的 `validate_input_derivatives`
在 cross-reference 檢查階段，把 `material`、`receptor`、`arrival`、
`initial_condition`、`boundary_geometries` 五個 component loader 包在同一個
`try`，`except Exception as exc:` 只記
`f"component_cross_reference_invalid:{type(exc).__name__}"`——只有例外型別名稱，
沒有訊息、沒有哪個 component、沒有 traceback。同時 `receptor`／`arrival` 的
loader 在這個 try 裡被重複呼叫兩次（一次獨立檢查，一次餵給
`load_receptor_arrival_initial_condition_manifest`），浪費一次可省略的 I/O。

`_write_artifact_directory` 的 `except Exception:` 區塊在任何例外（包含 validator
判定 `valid: False` 而主動拋出的 `InputDerivationError`）時都會
`shutil.rmtree(partial, ignore_errors=True)`，導致 validator 判定失敗留下的唯一
診斷線索（partial 目錄裡已寫出的各 component JSON）被整個刪除，事後只能重跑一次
完整建置才能重新診斷。

## 2. 改了什麼

### 2.1 `validate_input_derivatives`：逐 component try/except（約第 8181–8236 行）

把原本單一大 `try` 拆成五段，各自 try／except，並用一個
`component_cross_reference_ok: dict[str, bool]` 記錄每個 component 的成敗：

- `material`、`receptor`、`arrival`、`boundary_geometries` 四個彼此獨立，各自
  失敗時記成
  `f"component_cross_reference_invalid:{component}:{type(exc).__name__}:{exc}"`
  （component 名稱、例外型別、**完整原始例外訊息**，不截斷）。
- `receptor`、`arrival` 的 loader 現在**只呼叫一次**，回傳值存進
  `receptor_records`／`arrival_records`，`initial_condition` 檢查重用這兩個結果，
  不再重複呼叫。
- `initial_condition` 依賴 `receptor`／`arrival`：若兩者都成功才呼叫
  `load_receptor_arrival_initial_condition_manifest`；只要有一個先失敗，就記成
  `f"component_cross_reference_skipped:initial_condition:{failed_dependencies}"`
  （`failed_dependencies` 是以逗號分隔的失敗依賴名稱，兩個都失敗時會列出兩個），
  不再對已知會因缺前置資料而失敗的 loader 再拋一次容易誤導的例外。
- `_write_artifact_directory` 既有的「只取前 8 則 error」邏輯完全沒動。

### 2.2 `_write_artifact_directory`：validator 失敗時保留改名後的 partial（約第 6784–6809 行）

在 `if validation.get("valid") is not True:` 分支內：

1. 從 partial 目錄既有名稱（`f".{destination.name}.partial-{token}"`）解析出
   `token`。
2. 用 `os.replace(partial, invalid_dir)` 把它原地改名成同層、**非隱藏**的
   `<destination 名稱>.invalid-<token>`（沿用原本的隨機 token）。
3. 把 `partial` 重新指派成 `Path()`，讓外層 `except Exception:` 的
   `if partial and str(partial) not in {"", "."}: shutil.rmtree(...)` 判斷不到
   它，不會再被清掉。
4. 才 `raise InputDerivationError(...)`，訊息內附上 `invalid_dir` 的絕對路徑。

其餘例外（例如 validator 本身崩潰、不是明確的 `valid: False` 判定）完全沒有改
動路徑，仍會被外層 `except Exception:` 整個 `shutil.rmtree`。

### 2.3 文件

- `docs/operations/cli_reference.md`：在「inputs artifact 與 release config」段落

  名稱>.invalid-<token>`）、內容只供人工診斷、絕不是可發布母體、不會被任何 CLI
  自動當成 `--destination` 或 `--partial` 讀入，以及需要手動清除。

## 3. 改前改後的錯誤訊息範例

### 3.1 cross-reference validator 的 errors（`validate_input_derivatives` 回傳）

**改前**（規格描述的實際案例，只有型別名稱）：

```
component_cross_reference_invalid:ValueError
```

**改後**（本次測試用 `load_arrival_time_manifest` 拋出已知訊息實際驗證到的字串，
逐字取自測試輸出）：

```
component_cross_reference_invalid:arrival:ValueError:synthetic arrival loader 已知失敗訊息：時次 42 號缺少對應 receptor
component_cross_reference_skipped:initial_condition:arrival
```

### 3.2 `_write_artifact_directory` 拋出的 `InputDerivationError`

**改前**：

```
input artifact partial publish 前 cross-reference validator 失敗：component_cross_reference_invalid:ValueError
```

（同時 partial 目錄已被 `shutil.rmtree` 刪除，無法再讀。）

**改後**（測試用 `component_cross_reference_invalid:fixture:ValueError:模擬失敗訊息`
這個模擬 error 驗證到的訊息）：

```
input artifact partial publish 前 cross-reference validator 失敗：component_cross_reference_invalid:fixture:ValueError:模擬失敗訊息；保留供診斷的目錄：/tmp/.../derived-inputs.invalid-<token>
```

（`derived-inputs.invalid-<token>` 目錄確實留在磁碟上，內含已寫出的
`material.json` 等 component。）

## 4. 新增測試與驗證結果

全部新增／改寫在 `tests/test_input_derivation.py`：

1. **`test_validate_input_derivatives_reports_component_name_and_original_message`**
   （新增，緊接在 `test_input_validator_rejects_artifact_closure_tamper` 之前）：
   用 `synthetic_input_fixture` 先建出一份合法 artifact，再用
   `monkeypatch.setattr(input_derivation_module, "load_arrival_time_manifest",

   `validate_input_derivatives` 回傳的 `errors` 內同時含

   且 `initial_condition` 記成 `component_cross_reference_skipped:...:arrival`，
   同時確認 `material`／`boundary_geometries`（彼此獨立的 component）沒有被連帶
   誤報。
2. **`test_artifact_prepublish_cross_reference_failure_keeps_invalid_directory_for_diagnosis`**
   （改寫自原本的 `test_artifact_prepublish_cross_reference_failure_removes_partial`，
   同一測試位置）：用 monkeypatch 讓 `validate_input_derivatives` 回傳
   `valid: False`，驗證 `_write_artifact_directory` 拋出的 `InputDerivationError`
   訊息含「保留供診斷的目錄」字樣與路徑、磁碟上確實留下唯一一個
   `<destination名稱>.invalid-*` 目錄且內容包含 `material.json`、原本隱藏的
   `.partial-*` 目錄已不存在（因為改名走了），且正式 `destination` 目錄**沒有**
   被建立。
3. **`test_artifact_prepublish_generic_exception_still_removes_partial`**
   （新增，緊接在測試 2 之後）：讓 `validate_input_derivatives` 直接拋出
   `RuntimeError`（模擬 validator 自身崩潰，不是它主動判定的
   `valid: False`），驗證 partial 仍被整個清除、沒有留下任何
   `.partial-*` 或 `.invalid-*` 殘留、`destination` 也沒被建立——這是 2.2 節改動
   的回歸測試，確保只有「validator 明確判定失敗」這一條路徑才保留目錄。
